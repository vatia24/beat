# Beatroom

ორი ტელეფონით ერთი YouTube ვიდეოს მოსასმენად გახსენი საჯარო ოთახი iPhone-ზე Wi-Fi-ით და სტუმრის ბმული Android-ზე მობილური ინტერნეტით. ორივე ტელეფონი ვიდეოს უშუალოდ YouTube-ის ხილულ პლეერში უკრავს. მიკროფონის ნებართვა საჭირო არ არის.

## ლოკალური გაშვება

`package.json`-ის საქაღალდეში, Node.js 20.11 ან უფრო ახალი ვერსიით, შეასრულე ეს სამი ბრძანება.

```sh
npm ci
npm run build
npm start
```

გახსენი [ლოკალური საიტი](http://localhost:3000). ნაგულისხმევი პორტია `3000`. ორი სხვადასხვა ქსელიდან გამოცდისთვის გამოიყენე ქვემოთ აღწერილი საჯარო განთავსება.

## საჯარო HTTPS ოთახი Render-ზე

1. პროექტის ფაილები განათავსე GitHub-ის რეპოზიტორიაში. პროექტის ძირეულ საქაღალდეში უნდა იყოს `package.json`, `package-lock.json`, `server/`, `src/`, `public/` და `index.html`.
2. [Render Dashboard](https://dashboard.render.com)-ში აირჩიე **New → Web Service**, მიაბი რეპოზიტორია და აირჩიე მისი branch.
3. **Language** აირჩიე **Node**. **Root Directory** დატოვე ცარიელი, თუ `package.json` რეპოზიტორიის ზედა დონეზეა. თუ მთელი პროექტი ქვესაქაღალდეში შეიტანე, მიუთითე ამ საქაღალდის გზა რეპოზიტორიის ძირიდან.
4. **Build Command** ჩაწერე `npm ci --include=dev && npm run build`, **Start Command** — `npm start`, **Health Check Path** — `/healthz`. დატოვე **ერთი ინსტანსი**. სერვერი Render-ის `PORT`-ს ავტომატურად იყენებს.
5. აირჩიე **Deploy Web Service**. სტატუსის **Live** მიღების შემდეგ გახსენი Render-ის მიერ ნაჩვენები `https://…onrender.com` მისამართი. `/healthz` აბრუნებს `{"ok":true}`. ბრაუზერი ოთახის კავშირს იმავე დომენის `/ws`-ზე WSS-ით ხსნის.

ოთახები ამ ერთი სერვერის მეხსიერებაშია. სერვერის გადატვირთვის, ხელახალი განთავსების ან დაძინების შემდეგ შექმენი ახალი ოთახი. მასპინძლის მართვის უფლება იმავე ჩანართში ინახება. სტუმრებისთვის გამოიყენე ამ ოთახის გაზიარების ბმული ან QR. [Render-ის Node.js ინსტრუქცია](https://render.com/docs/deploy-node-express-app) · [WebSocket Render-ზე](https://render.com/docs/websocket)

## Vercel-ზე განთავსება Render-ის ოთახის სერვერით

1. ჯერ გაუშვი ზემოთ აღწერილი ერთი Render Web Service. დააკოპირე მისი რეალური საჯარო მისამართი, მაგალითად `https://name.onrender.com`.
2. Vercel Dashboard-ში აირჩიე **Add New → Project**, მიაბი იგივე Git რეპოზიტორია და **Root Directory** მიუთითე საქაღალდეზე, სადაც `package.json` და `vercel.json` დევს. **Framework Preset** ველში აირჩიე **Vite**, **Install Command** ველში ჩაწერე `npm ci --include=dev`, **Build Command** ველში — `npm run build`, ხოლო **Output Directory** ველში — `dist`.
3. პირველი **Deploy**-ის წინ, **Environment Variables**-ში Production-ისთვის დაამატე `VITE_ROOM_SERVER_ORIGIN` და მნიშვნელობად ჩაწერე Render-ის სრული HTTPS მისამართი, გზისა და ბოლო `/`-ის გარეშე. Vite ამ მნიშვნელობას აწყობისას კითხულობს. თუ ცვლადი მოგვიანებით შეცვალე, Vercel-ის **Deployments**-იდან ხელახლა გაუშვი Production-ის **Redeploy**. [Vite-ის გარემოს ცვლადები](https://vite.dev/guide/env-and-mode)
4. Vercel-ის **Settings → Domains**-იდან აიღე პროექტის სტაბილური Production დომენი. Render-ის შესაბამის სერვისში გახსენი **Environment**, დაამატე `PUBLIC_ORIGIN` ზუსტად ამ მნიშვნელობით, მაგალითად `https://name.vercel.app`, და აირჩიე **Save and deploy**. ეს მისამართი განსაზღვრავს რომელი საიტიდან მიიღებს სერვერი ოთახის შექმნისა და WebSocket კავშირის მოთხოვნებს. [Render-ის გარემოს ცვლადები](https://render.com/docs/configure-environment-variables)
5. ორივე ტელეფონზე გამოიყენე Vercel-ის Production მისამართი. შექმენი ოთახი და გახსენი მისივე QR. `vercel.json`-ის წესი სტუმრის პირდაპირ `/r/…` ბმულს React აპში ხსნის. არჩეულ ოთახში მონაცემები Render-ის `/ws`-ზე WSS-ით გადის. [Vite Vercel-ზე](https://vercel.com/docs/frameworks/frontend/vite)

Vercel Functions-ში WebSocket მხარდაჭერა 2026 წლის 20 ოქტომბრიდან ზოგადად ხელმისაწვდომია. მთლიანად Functions-ზე გადასვლისას ახალი კავშირები შეიძლება სხვადასხვა ინსტანსს შეხვდეს, ღია კავშირებს კი ფუნქციის დროის ლიმიტი აქვს. ამისთვის სერვერს დასჭირდება ოთახის საერთო საცავი და შეტყობინებების განაწილება (მაგალითად Redis და Pub/Sub), პროცესებს შორის შედარებადი სესიის საათი და ვადის გასვლის შემდეგ კავშირის აღდგენა. [Vercel-ის გამოშვება](https://vercel.com/changelog/websocket-support-is-now-generally-available) · [კავშირები და მდგომარეობა ინსტანსებს შორის](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)

## ორი ტელეფონით მოსმენა

1. iPhone-ზე Safari-თი გახსენი განთავსებული საიტი და დააჭირე **ოთახის შექმნა**. ჩასვი YouTube ვიდეოს ბმული და დააჭირე **არჩევა**. პირველ ცდად გამოდგება Jim Dooley-ის 90 BPM დრამი, ხანგრძლივობით 20:37. შემოწმებისას YouTube ამ ვიდეოს ოფიციალურ embed-ს აბრუნებდა. [სატესტო ვიდეო](https://www.youtube.com/watch?v=bqcPx0KRsRM)
2. Android-ზე გამორთე Wi-Fi და გახსენი ოთახის QR ან ბმული Chrome-ში. ტელეფონები დადე გვერდიგვერდ, მსგავსი ხმის დონით. გამოიყენე ჩაშენებული დინამიკები და ორივე ეკრანი დატოვე ხილული.
3. **პირველი დარტყმა.** სტუმარი აჭერს **ხმის ჩართვა ამ ტელეფონზე**, შემდეგ მასპინძელი — **ყველასთვის დაკვრა**. ჩაინიშნე, პირველი დარტყმა ერთჯერადად გაისმა თუ გაორდა, ორივე მოწყობილობა ნამდვილად უკრავდა თუ არა და დასჭირდა თუ არა სტუმარს მეორე შეხება. თუ ბრაუზერი ამას ითხოვს, დააჭირე ▶ უშუალოდ ხილულ ვიდეოში. ახალი სტარტის გამოსაცდელად ტრეკი თავიდან აირჩიე ან შექმენი ახალი ოთახი.
4. **შუაში შეერთება.** სტუმარმა დახუროს ოთახის გვერდი და კვლავ გახსნას ბმული, სანამ iPhone-ზე ტრეკი უკრავს. წამზომით გაზომე დრო სტუმრის ხმის ჩართვის ღილაკიდან იმ მომენტამდე, როცა ორივე დინამიკზე რიტმი ერთიანად ისმის. ცალკე ჩაინიშნე რეკლამა, პლეერზე დამატებითი შეხება ან ხელით სინქრონიზაცია. როცა ერთიანი რიტმი არ დგება, ასე ჩაწერე შედეგშიც.
5. **ათი წუთი.** ცალკე გაშვებაზე მოუსმინე ათი წუთი ხელით ჩარევის გარეშე. ჩაინიშნე პირველი გასაგონი ორმაგი დარტყმის, ხმის წყვეტის ან შესამჩნევი რიტმული აცდენის დრო. ავტომატური კორექცია გამორთულია. საბაზისო ცდის დასრულების შემდეგ, მხოლოდ იმ ტელეფონზე, რომლის გასწორებაც გინდა, დააჭირე **ხელახლა სინქრონიზაცია** და კვლავ შეაფასე ხმა. მეორე ტელეფონი დაკვრას აგრძელებს.

დიაგნოსტიკაში **კავშირის RTT** არის სერვერთან მიმოსვლის დრო. **პლეერის შეფასებული აცდენა** არის YouTube-ის პოზიცია მინუს იმავე მომენტისთვის გამოთვლილი სამიზნე პოზიცია. დადებითი მნიშვნელობა პლეერის წინ ყოფნას ნიშნავს. დინამიკებიდან დარტყმის დამთხვევა შეაფასე მოსმენით. ერთი მოწყობილობის რეკლამა, ჩატვირთვა ან დაბრუნება ოთახის პაუზას არ იწვევს.
